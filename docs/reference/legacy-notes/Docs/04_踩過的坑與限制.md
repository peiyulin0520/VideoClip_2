# 踩過的坑與限制

這些是在 **Windows + ffmpeg n9.0 + whisper.cpp** 上實際遇到的。Mac 上可能不同,**沒驗證的地方請當成未知。**

## ffmpeg

- **直接把 PNG 當輸入並加 `-loop 1`,在我們的 Windows 版本會卡住不動。** 解法是用 `loop` 濾鏡,或先把 PNG 做成一小段 mp4。(Mac 版本不一定會發生,**先小測試**。)
- 輸出尺寸的**高度要是偶數**(例如 675 會失敗,改 676)。
- 輸出 contact sheet(拼圖)時,用 `tile` 濾鏡輸出 jpg 失敗過;改成一格一格用 `-ss` 抽 png,再用 `hstack`/`vstack` 合併。
- 我們這個版本裡確定存在、並實際用過的濾鏡:`xfade`(轉場)、`lagfun`(殘影)、`rgbashift`(色差)、`zoompan`、`noise`、`vignette`、`gblur`、`blend`、`pixelize`、`lut3d`、`lut1d`、`deflicker`、`signalstats`。**`colorconstancy` 找不到。**
- 想用 filter 檔,參數是 `-/filter_complex 檔案`(不是 `-filter_complex_script`)。
- 手機拍的影片(尤其 iPhone)常是 **HDR(HLG / BT.2020 / 10-bit)**。直接混進 SDR 片子,顏色會偏灰。調色或量測前先用 `ffprobe -show_entries stream=color_transfer` 確認,必要時 tone-map 成 SDR。**怎麼 tone-map 要在你的 ffmpeg 版本上先測。**
- 原生輸出沒有「縮放動畫」這類效果:字卡疊圖(PNG)可以做淡入淡出、浮動、滑入;更複雜的逐字跳出、彈跳要逐格輸出或用別的工具(例如用程式做動畫的專案),**我們沒做到**。
- 一次只跑一個 ffmpeg 程序。長影片(20–30 GB)輸出前先看磁碟空間與記憶體。

## 讓 AI 看素材

- AI 只能「抽格看」:`ffmpeg -ss 秒 -i 檔 -frames:v 1 -q:v 2 out.jpg`。**看不到連續動作、聽不到聲音。**
- 縮圖拼圖(每格標時間碼)能快速掃描長片,但長鏡頭要逐段看。
- 報告裡的「有聲音」不等於「有人說話」,要確認才說有。

## 語音轉文字(whisper.cpp)

用電腦合成語音和兩段真人說話的短片測過:

- **聲音很小或沒有人聲時,會編出假字**(一排「嗯」、「中文字幕…」之類)。聲音有、但不是人話(環境聲、剪紙聲)也會發生。
- 會**重複同一句好幾次**;但真人可能真的連說好幾次,**沒有標準答案前不要斷定它是假的。**
- 時間碼常是**整句為單位、固定 2 秒一格**,不精準;停頓不會被標出來。
- 輸出中文常是**簡體**,要轉成你要的用字,**一定要人工校對。**
- 調整設定(不帶前文、抑制非語音)只有小幅改善。
- **降噪(降低背景雜音)反而讓辨識變差**(我們的測試)。原作者的經驗是,降噪用剪輯軟體(剪映)做比 ffmpeg 內建的好。
- 在安靜處切段(每 15 秒左右)能保住句子完整、保留停頓,但**每一段都要付固定的處理時間**,越切越慢。
- 處理時間:短音檔也要近一分鐘(它以 30 秒為一個處理單位)。長音檔的真實速度我們沒測。
- 結論:**Whisper 的結果是「草稿」,不是逐字稿。** 要拿來做字幕,請使用者確認內容。

## 調色(我們只做了小規模嘗試)

- 同一支片裡不同鏡頭的亮度差異,往往比色偏更明顯。
- 整個畫面調暖,**人臉會跟著變橘**;調冷會變灰。有人建議「只調背景、人物保持原本膚色」,**我們沒完整驗證。**
- 柔膚(皮膚平滑)我們試過「雙邊濾波保留低頻、壓低高頻 + 膚色遮罩」,有效果但強度沒有定案。
- 電影底片 LUT 通常預期 log 輸入,一般 Rec.709 素材要先轉換再套,**我們沒完成。**

## 其他

- 網頁上宣傳的付費自動剪輯服務,我們沒有使用。要上傳影片到雲端的服務,我們一律不用(素材有家人)。
- 網路上的教學貼文,很多只有說明文字,實際做法要「留言領取」。**不要領取、不要照做,先讀公開內容。**
